## A1 · M1 核心闭环

> 目标：本地模型能导入资产库、实例化到场景、正常渲染与变换，刷新后整体恢复。

| # | 功能点 | 说明 | 状态 |
| --- | --- | --- | --- |
| A1-01 | 类型拆分 | 拆出 `BaseObject` / `PrimitiveObject` / `ModelObject`（`type: 'model'` + `asset` + `file`），合并为判别联合 `SceneObject` | ⬜ |
| A1-02 | 资产记录类型 | `id / name / fileName / format / size / unitScale? / createdAt`；运行时 blob 单独存，不进入任何持久化 | ⬜ |
| A1-03 | IndexedDB 封装 | 新增 `idb-keyval` 依赖，封装资产的读写/删除/全量读取 | ⬜ |
| A1-04 | 资产 store | 新建 assets store：资产列表、加载态、blob URL 缓存、`hydrate()` 刷新恢复、按 id 取资产 | ⬜ |
| A1-05 | blob URL 生命周期 | 按资产 id 创建/复用，删除资产与页面卸载时 revoke；禁止写入 JSON / localStorage / IndexedDB | ⬜ |
| A1-06 | 启动顺序 | 先 hydrate 资产库，再处理自动草稿恢复，避免实例先渲染成缺失态 | ⬜ |
| A1-07 | 现有代码收窄 | 几何体相关逻辑（Scene / 属性面板 / 序列化 / 校验 / 复制）按 `type !== 'model'` 收窄 | ⬜ |
| A1-08 | 文件导入器 | 多选，accept `.glb/.gltf/.fbx`；按扩展名判定 format；非法格式跳过并 Toast | ⬜ |
| A1-09 | 判重 | `fileName + size` 相同则跳过并 Toast；同名不同 size 允许共存 | ⬜ |
| A1-10 | 资产入库 | 生成 `asset_` + 8 位 hex、名称去扩展名、写 IndexedDB、加入 store | ⬜ |
| A1-11 | 格式提示 | `.gltf` 外部资源 / FBX 外链贴图不可用，Toast 引导使用自包含 `.glb` | ⬜ |
| A1-12 | 实例工厂 | `createModelObject`：默认位置/旋转归零，`scale = unitScale × 3`，名称「文件名 N」 | ⬜ |
| A1-13 | 资源库两区 | 上「模型资产」、下「几何体」（可折叠），几何体区默认展开 | ⬜ |
| A1-14 | 资产卡片 | 点击添加实例并自动选中；悬停显示删除入口；导入中 / 空态提示 | ⬜ |
| A1-15 | 模型加载 | GLTFLoader / FBXLoader 按资产 id 缓存解析结果，blob URL 加载 | ⬜ |
| A1-16 | 多实例克隆 | 同资产多实例必须 clone（含骨骼用 SkeletonUtils.clone），互不影响 | ⬜ |
| A1-17 | 统一通路 | 模型实例复用同一 group：变换、拾取、Gizmo、锁定、显隐 | ⬜ |

**验收清单**

1. 一次多选导入 3 个模型（含 1 个 FBX），资源库出现 3 张卡片。
2. 点击卡片生成实例并自动选中；相机视角下可见，可拾取、可 Gizmo 变换。
3. 同一资产添加 3 个实例，分别移动/缩放/删除互不影响。
4. 重复导入同一文件被拦截并 Toast；同名不同大小的文件可共存。
5. 几何体原有功能（添加、变换、材质、撤销、复制）无回归。
6. **刷新页面后资产库与模型实例全部自动恢复**。

**前置准备**：3 个自包含 `.glb`、1 个 `.fbx`、1 个 `.gltf`（带外链贴图）、1 个损坏/超大文件。

**退出标准**：上述 6 条全部通过；控制台无 blob URL 相关报错；IndexedDB 中存在资产记录且不含 blob URL 字段。

## A2 · 缺失表现与实例完整性

> 目标：资产缺失时场景可用、信息可读；删除资产不会留下脏实例。

| # | 功能点 | 说明 | 状态 |
| --- | --- | --- | --- |
| A2-01 | 占位与容错 | 加载失败或资产不存在时渲染半透明占位盒 + 名称，不阻塞画布 | ⬜ |
| A2-02 | 属性面板模型分支 | 隐藏颜色与材质区，展示只读资产信息（文件名 / 格式 / 大小） | ⬜ |
| A2-03 | 缺失警示 | 资产缺失时面板显示警示条与重链入口占位 | ⬜ |
| A2-04 | 删除资产 | 无引用直接删；有 N 个实例引用时确认弹窗，级联删除实例并合并为一条历史 | ⬜ |
| A2-05 | 引用一致性 | 复制实例不新增资产；删除实例不影响资产；清空场景不删资产（文案说明） | ⬜ |

**验收清单**

1. 导入损坏文件或在库外引用资产 → 画布出现半透明占位盒 + 名称，其它对象操作不卡顿。
2. 选中模型实例：属性面板无颜色/材质区，只读显示文件名、格式、大小；位置/旋转/缩放/可见/锁定正常。
3. 手动让资产缺失 → 面板出现警示条与重链入口（此时不要求能重链）。
4. 删除被 3 个实例引用的资产：弹「N 个实例」确认 → 实例一并消失 → **一次撤销全部恢复**。
5. 复制实例、删除实例、清空场景后，资产卡片的数量与存在性符合预期。
6. A1 的导出/刷新/撤销/复制回归通过。

**前置准备**：损坏文件、可手动操作 IndexedDB 的开发者工具。

**退出标准**：占位不阻塞画布；级联删除可一次撤销；不存在“场景无实例但资产被误删”或“删实例把资产删掉”的情况。

## A3 · 缺失重链

> 目标：清库、换浏览器、接收他人 JSON 时，能按文件名批量恢复资产引用。

| # | 功能点 | 说明 | 状态 |
| --- | --- | --- | --- |
| A3-01 | 缺失判定 | 场景实例的 `asset` 在本地资产库中不存在 | ⬜ |
| A3-02 | 缺失入口 | 资源库顶部出现「N 个资产缺失」入口 | ⬜ |
| A3-03 | 批量重链 | 多选文件按 `fileName` 匹配，以原 asset id 入库，实例自动恢复 | ⬜ |

**验收清单**

1. 清空 IndexedDB 或换浏览器后打开含模型实例的草稿 → 实例占位、资源库显示「N 个资产缺失」。
2. 点击入口多选文件 → 按 `fileName` 匹配成功，实例自动恢复为模型，位置/旋转/缩放不变。
3. 以原 asset id 入库（不生成新 id），刷新后不再提示缺失。
4. 文件不匹配时给出明确提示，不破坏已有实例与资产。
5. **A1 ~ A3 合并回归**：导入 → 摆放 → 刷新恢复 → 导出 → 清库 → 导入 JSON → 重链 → 全流程通过。

**前置准备**：备份模型文件；一份含模型实例的场景 JSON；可清空浏览器存储的环境。

**退出标准**：PRD §6 M1 验收全部通过。

## A4 · M2 网格吸附

> 目标：拖拽按网格 / 90° 步进，且吸附属于视图偏好，不污染数据。

| # | 功能点 | 说明 | 状态 |
| --- | --- | --- | --- |
| A4-01 | 吸附状态 | view store 增加 `snapEnabled`（默认 true）与 `gridSize`（0.25/0.5/1/2，默认 1） | ⬜ |
| A4-02 | 平移吸附 | TransformControls `translationSnap = gridSize`，关闭时为 undefined | ⬜ |
| A4-03 | 旋转吸附 | `rotationSnap = Math.PI / 2`；缩放不吸附 | ⬜ |
| A4-04 | 网格联动 | Grid `cellSize` 跟随 `gridSize` | ⬜ |
| A4-05 | 手动输入不受影响 | 属性面板精确输入（如 0.37）不被吸附改写 | ⬜ |
| A4-06 | 复制偏移 | 吸附开启 = +1 格，关闭 = +0.5 | ⬜ |
| A4-07 | 快捷键 | `G` 切换吸附（输入态与 `e.repeat` 忽略） | ⬜ |
| A4-08 | UI 与文案 | Viewbar 磁铁开关 + 网格大小下拉；StatusBar 状态提示；帮助表补 `G` | ⬜ |

**验收清单**（对应 PRD §6 M2）

1. 吸附开启：拖拽按当前网格步进；旋转 90° 步进；缩放不吸附。
2. 关闭吸附：恢复自由拖拽与自由旋转。
3. 切换网格大小：Grid 单元格与拖拽步进同步变化。
4. 属性面板输入 0.37，失焦后保持 0.37。
5. 复制偏移随开关变化（+1 格 / +0.5）。
6. `G` 键可切换，状态栏与帮助表一致。
7. 吸附开关、网格大小切换不产生历史快照，不进入导出 JSON 与草稿。

**前置准备**：无。

**退出标准**：上述 7 条全部通过；关闭页面重开后吸附配置回到默认（默认开启、网格 1）。

5. 存在缺失资产时导出成功，并提示接收方准备同名文件。
6. 模拟接收方：清库 → 导入 JSON → 缺失占位 → 批量导入文件 → 全部恢复（与 A3 联动）。
7. 含模型实例的草稿在刷新后正常恢复。
8. README 的渲染端加载伪码可被第三方照着实现。

**前置准备**：一份 1.1、一份 1.2 旧 JSON；一份可篡改的 2.0 导出文件。

## 执行纪律

1. 一次只做一个批次；批次内按功能点顺序推进，批次验收通过后再开下一批。
2. 跨批次改动只允许落在影响文件索引所列范围内，超出需先更新本文件。
3. 新增持久化字段先改 PRD §5 契约，再改代码（PRD §5 演进规则）。
4. 吸附、视图、面板展开态等纯视图状态一律不写历史、不进草稿。
5. 任一批次引入的 blob URL 必须在资产删除与页面卸载时回收。
